# FRAME PRODUCTION — საიტის ფაილები და გამოყენების ინსტრუქცია

განახლებულია: 5 ოქტომბერი, 2026.

საიტი FRAME-ს აღწერს როგორც ვიდეოპროდაქშენის გუნდს, რომელიც სხვადასხვა კომპანიისთვის ვიდეოებს ქმნის. ტექსტები განახლებულია ინგლისურად და ქართულად. შენარჩუნებულია დიზაინი, შემცირებული სათაურები, მუქი რეჟიმი, ენის გადართვა, კურსორი, პროექტები და ვიდეოპლეერი.

ამ ZIP-ში არის საიტის სრული საწყისი კოდი, არსებული სურათები და პოსტერები, დამოკიდებულებების ზუსტი სია და გამზადებული `dist` ვერსია. `node_modules` არ არის ჩადებული: ის ქვემოთ მოცემული ბრძანებით აღდგება. ადმინისტრირების პანელი და სერვერული ბაზა საიტს არ სჭირდება.

MP4-ები ჯერ არ არის ჩადებული, რადგან ფაილები არ გამოგიგზავნია. ამიტომ ამ ვერსიაში ექვსივე არსებული YouTube ბმული მუშაობისთვის დატოვებულია. შეცვალე თითოეული ბმული მხოლოდ შესაბამისი MP4-ის დამატების შემდეგ.

## 1. ZIP-ის გახსნა და მომზადება Windows-ზე

1. ZIP-ზე დააჭირე მარჯვენა ღილაკს → **Extract All**. ფაილები მთლიანად ამოიღე; ZIP-ის შიგნიდან ნუ დაარედაქტირებ.
2. გახსენი ამოღებული `frame-production-website` საქაღალდე. მასში უნდა ჩანდეს `frontend`, `dist` და ეს `README.md`.
3. დააყენე [Node.js-ის LTS ვერსია](https://nodejs.org/en/download). აირჩიე Windows Installer და სტანდარტული პარამეტრები. ინსტალაციის შემდეგ ხელახლა გახსენი ტერმინალი.
4. კოდის შესაცვლელად გამოიყენე [Visual Studio Code](https://code.visualstudio.com/). გახსენი **File → Open Folder** და აირჩიე `frame-production-website`.
5. Windows Explorer-ში ჩართე **View → Show → File name extensions**, რომ ფაილი შემთხვევით `alex-topuria.mp4.mp4` არ გახდეს.

მნიშვნელოვანი საქაღალდეები:

| მდებარეობა | დანიშნულება |
| --- | --- |
| `frontend/src/data/projects.js` | პროექტების ვიდეოები, პოსტერები და აღწერები |
| `frontend/public/videos/` | აქ უნდა ჩაყარო MP4-ები |
| `frontend/public/media/posters/` | პროექტების არსებული პოსტერები |
| `frontend/src/data/georgian.js` | ქართული თარგმანები |
| `frontend/public/_redirects` | Netlify-ზე შიდა გვერდების პირდაპირ გახსნას უზრუნველყოფს |
| `dist/` | ჰოსტინგზე ასატვირთი გამზადებული საიტი |

## 3. YouTube ბმულების შეცვლა კოდში

გახსენი `frontend/src/data/projects.js`. ეს საიტი JavaScript-ს იყენებს: ფაილი არის `.js`, არა `.ts`.

**Alex Topuria:** მოძებნე:

```js
video: "https://youtu.be/hqicKFbszks",
```

და ჩაანაცვლე:

```js
video: "/videos/alex-topuria.mp4",
```

**Mate Motors:** მის ობიექტში მთავარი ვიდეო გახდება:

```js
video: "/videos/mate-motors-01.mp4",
```

იმავე პროექტის `additionalVideos` შეცვალე ასე:

```js
additionalVideos: [
  { src: "/videos/mate-motors-02.mp4", label: "MATE MOTORS — FILM 02" },
],
```

**დანარჩენი სამი პროექტი:** თითოეულის საკუთარ ობიექტში მხოლოდ `video` მნიშვნელობა შეცვალე:

```js
// SOCAR
video: "/videos/socar.mp4",

// ZOOPLUS
video: "/videos/zooplus.mp4",

// BRUNCH & DINE
video: "/videos/brunch-and-dine.mp4",
```

ეს სამი სტრიქონი ერთ პროექტში არ ჩასვა — თითოეული თავის პროექტს ეკუთვნის. არ დაამატო მეორე `video` ველი. შეინარჩუნე ბრჭყალები და მძიმეები, შემდეგ დააჭირე **Ctrl+S**.

კოდში მისამართი იწყება `/videos/`-ით. მასში არ უნდა ჩაწერო `frontend/public`, Windows-ის `C:\...` მისამართი ან უკუღმა დახრილი ხაზი. მაგალითად, დისკზე `frontend/public/videos/socar.mp4` ბრაუზერისთვის არის `/videos/socar.mp4`.

პლეერს შეცვლა არ სჭირდება: პირდაპირი MP4 მისამართის მიღებისას ის იყენებს ბრაუზერის ვიდეოპლეერს. ვიდეოს ჩამოტვირთვა იწყება პოსტერის დაჭერის შემდეგ. პოსტერის ფოტო და ვიდეო ცალ-ცალკე ფაილებია.

## 4. პოსტერების, მთავარი ფოტოსა და Showreel-ის შეცვლა — სურვილის შემთხვევაში

ეს ცვლილებები აუცილებელი არ არის MP4-ების დასამატებლად.

პროექტის პოსტერისთვის ჩასვი, მაგალითად, `socar.jpg` ფაილი `frontend/public/media/posters/` საქაღალდეში. SOCAR-ის ობიექტში შეცვალე:

```js
poster: "/media/posters/socar.jpg",
```

არსებული გრაფიკული პოსტერები ავტომატურად არ შეიცვლება MP4-იდან ამოღებული კადრით. თუ გინდა რეალური ვიდეოკადრი, ის ცალკე გამოიტანე JPG/WebP ფორმატში და მიუთითე `poster` ველში.

მთავარი ფოტოსთვის ჩასვი `hero.jpg` ფაილი `frontend/public/media/`-ში. `projects.js`-ის ბოლოში შეცვალე მთელი `HERO_IMAGE` გამოცხადება:

```js
export const HERO_IMAGE = "/media/hero.jpg";
```

Showreel-ის დამატებისას `showreel.mp4` ჩასვი `frontend/public/videos/`-ში და არსებული ორსტრიქონიანი `SHOWREEL_VIDEO = null;` მთლიანად შეცვალე:

```js
export const SHOWREEL_VIDEO = "/videos/showreel.mp4";
```

ამის შემდეგ მთავარი გვერდის Showreel ღილაკიც გააქტიურდება.

## 5. საიტის შემოწმება საკუთარ კომპიუტერზე

1. Explorer-ში გახსენი ის საქაღალდე, რომელშიც `frontend` და `dist` დევს.
2. Explorer-ის მისამართის ზოლში ჩაწერე `cmd` და დააჭირე Enter-ს. ასე Command Prompt ზუსტად ამ საქაღალდეში გაიხსნება.
3. პირველად გაუშვი:

```bat
npm ci --prefix frontend
```

დაელოდე დასრულებას. ინტერნეტი საჭიროა დამოკიდებულებების ჩამოსატვირთად. ეს ბრძანება ყოველ ვიდეოს შეცვლაზე აღარ გჭირდება.

4. შემდეგ გაუშვი:

```bat
npm run dev --prefix frontend
```

5. ბრაუზერში გახსენი ტერმინალში ნაჩვენები **Local** მისამართი; ჩვეულებრივ ეს არის `http://localhost:5173`.
6. Work გვერდიდან გახსენი ყველა პროექტი და დააჭირე Play-ს. Mate Motors-ში ორივე ვიდეო შეამოწმე. გადაამოწმე ხმა, სრული ეკრანი, ქართული/ინგლისური ენა და მუქი რეჟიმი.
7. ბრაუზერში პირდაპირ სცადე `http://localhost:5173/videos/socar.mp4` — გამოიყენე შენი ტერმინალის რეალური პორტი. თუ ვიდეო აქაც არ იხსნება, ფაილი, სახელი ან კოდეკი გადასამოწმებელია.
8. სერვერის გასაჩერებლად ტერმინალში დააჭირე **Ctrl+C**.

`index.html`-ზე ორმაგი დაწკაპუნება ადგილობრივი შემოწმების სწორი გზა არ არის: React საიტს სერვერიდან გახსნა სჭირდება.

## 6. ჰოსტინგისთვის გამზადება

იმავე მთავარ საქაღალდეში გაუშვი:

```bat
npm run build --prefix frontend
```

წარმატებისას განახლდება მთავარი საქაღალდის **`dist/`**. ამ პროექტში ის `frontend`-ის გვერდითაა, არა მის შიგნით.

- კოდის ან `frontend/public`-ის ფაილების შეცვლის შემდეგ ყოველთვის თავიდან გაუშვი build.
- ასატვირთი არის ბოლო build-ის სრული `dist` საქაღალდე.
- `dist`-ში ხელით გაკეთებული ცვლილებები შემდეგმა build-მა შეიძლება წაშალოს. ვიდეოები მუდმივად შეინახე `frontend/public/videos/`-ში.
- შეამოწმე, რომ `dist/videos/` შეიცავს ექვსივე MP4-ს და `dist/_redirects` არსებობს.
- `_redirects` უკვე დამატებულია; მისი `/* /index.html 200` წესი Netlify-ზე შიდა მისამართების განახლებას უზრუნველყოფს.

მხოლოდ ჩამოტვირთული ვერსიის უცვლელად განთავსება თუ გინდა, ZIP-ის `dist` უკვე გამზადებულია, მაგრამ ის ჯერ YouTube ბმულებს იყენებს.

## 7. უფასო ჰოსტინგი Netlify-ზე

ამ საიტისთვის მარტივი გზაა **Netlify Free**. GitHub-ის საცავი აუცილებელი არ არის. `.netlify.app` მისამართს მიიღებ; საკუთარი `.ge` ან `.com` დომენის შეძენა ცალკე ხარჯია.

### 7.1. ანგარიში და პირადი რეჟიმი

1. გახსენი [Netlify](https://app.netlify.com/) და შექმენი ანგარიში ან შედი.
2. აირჩიე **Free** გეგმა.
3. პირველ ატვირთვამდე ნახე **Team settings → General → Visitor access → Default project visibility** და აირჩიე **Private for new projects**. სხვადასხვა ასაკის ანგარიშს განსხვავებული საწყისი პარამეტრი შეიძლება ჰქონდეს.
4. პირად რეჟიმში შეამოწმე საიტი. უფასო გეგმაზე პირადი პროექტი მხოლოდ ანგარიშის მფლობელისთვისაა ხელმისაწვდომი; კლიენტს მარტო ბმულის გაგზავნით ვერ დაათვალიერებინებ.

### 7.2. ატვირთვა MP4-ებით — რეკომენდებული გზა

დიდი ფაილებისთვის გამოიყენე Netlify CLI. ინსტალაცია ერთხელ დაგჭირდება. Command Prompt კვლავ მთავარ საქაღალდეში უნდა იყოს, სადაც `dist` ჩანს.

```bat
npm install -g netlify-cli
netlify login
```

გაიხსნება ბრაუზერი. შედი შენს Netlify ანგარიშში და დაუკავშირე CLI.

შემდეგ ატვირთე უკვე გამზადებული `dist` პირადი განხილვისთვის:

```bat
netlify deploy --dir=dist --no-build
```

პირველი გაშვებისას აირჩიე ახალი პროექტის შექმნა (**Create & configure a new site**, ან იმავე მნიშვნელობის ვარიანტი), შენი Free გუნდი და თავისუფალი სახელი, მაგალითად `frame-production-ge`. თუ ასეთი სახელი დაკავებულია, აირჩიე სხვა. თუ უკვე შექმნილი გაქვს ეს პროექტი, აირჩიე არსებული; ყოველ ჯერზე ახალ პროექტს ნუ შექმნი.

ბრძანების დასრულებისას გახსენი მიღებული Draft Deploy URL. **Draft** თავისთავად პირადობას არ ნიშნავს — წვდომას ზემოთ არჩეული Project visibility განსაზღვრავს.

როცა შემოწმებული ვერსია მთავარ მისამართზე გინდა, გაუშვი:

```bat
netlify deploy --dir=dist --no-build --prod
```

`--no-build` საჭიროა იმიტომ, რომ საიტი უკვე ადგილობრივად ააწყე. `--prod` მას პროექტის მთავარ მისამართზე ათავსებს; Private პარამეტრი ცალკე განსაზღვრავს, ვის შეუძლია მისი ნახვა.

### 7.3. პატარა საიტისთვის უფრო მარტივი ალტერნატივა

თუ თითოეული ფაილი პატარაა, შედი [Netlify Drop](https://app.netlify.com/drop)-ზე და გადაათრიე **`dist` საქაღალდე**. მანამდე შეამოწმე პირადი რეჟიმის პარამეტრი და დარწმუნდი, რომ ანგარიშში შესული ხარ.

Netlify-ის დოკუმენტაცია Drag & Drop-ისთვის ურჩევს 50 MB-ზე პატარა მთლიან ატვირთვას და აღნიშნავს, რომ 10 MB-ზე დიდი ცალკეული ფაილები შეიძლება გაიჭედოს. MP4-ებით ამ ზომებს ადვილად გადააჭარბებ, ამიტომ ასეთ შემთხვევაში გამოიყენე 7.2-ში აღწერილი CLI. ეს რეკომენდაციაა Drag & Drop-ის საიმედოობისთვის და არა ყველა ატვირთვის ერთიანი მკაცრი ლიმიტი.

### 7.4. როდის ხდება საიტი ყველასთვის ხილული

ეს ნაბიჯი მხოლოდ მაშინ შეასრულე, როცა თავად გადაწყვეტ საჯაროდ გახსნას:

1. წარმატებული production deploy-ის შემდეგ პროექტის გვერდზე აირჩიე **Make public**; ან **Project configuration → General → Visitor access → Project visibility**-ში შეცვალე production წვდომა **Public**-ზე.
2. დაადასტურე არჩევანი. ამ მომენტიდან საიტს მისამართით ნებისმიერი ადამიანი ნახავს.
3. მიღებული მთავარი `https://შენი-სახელი.netlify.app` მისამართი გახსენი ინკოგნიტო ფანჯარაში, რათა დარწმუნდე, რომ კლიენტსაც ექნება წვდომა.
4. გადაამოწმე მობილურითაც და შემდეგ გაუგზავნე კომპანიებს.

ამ ცვლილებების შესრულებისას ახალი ვერსია საჯაროდ არ გამომიქვეყნებია. არსებული ChatGPT Sites ბმულის წვდომა შემოწმებისას Public იყო, ამიტომ იქ განახლება არ განთავსებულა. ZIP-იდან სხვა ჰოსტინგზე ატვირთვისას წვდომას ახალი ჰოსტინგის პარამეტრები განსაზღვრავს; არქივი თავისთავად პირადი წვდომის დაცვას არ შეიცავს.

## 8. რას ნიშნავს „უფასო“ ვიდეოებიანი საიტისთვის

5 ოქტომბრის, 2026 წლის შემოწმებით Netlify Free-ს აქვს თვეში **300 კრედიტი**. Production deploy მოიხმარს 15 კრედიტს; გადაცემული მონაცემები — 20 კრედიტს თითო GB-ზე; მოთხოვნებიც ითვლება. ლიმიტის ამოწურვისას საიტები პაუზდება. Free გეგმა შეუზღუდავი ვიდეოჰოსტინგი არ არის.

მაგალითად, 50 MB ფაილის 100 სრულად ჩამოტვირთვა დაახლოებით 5 GB-ს გადასცემს, ანუ მხოლოდ ამ მონაცემების გადაცემა დაახლოებით 100 კრედიტია. ეს საორიენტაციო ანგარიშია: რეალური მოხმარება ყურების ხანგრძლივობაზე, განმეორებით ჩატვირთვასა და ქეშზეა დამოკიდებული.

დასაწყისისთვის მოკლე, ზომიერად შეკუმშული MP4-ები შეიძლება საკმარისი იყოს. აკონტროლე **Usage & billing**. თუ ბევრი ნახვა იქნება, შეგიძლია ზოგ პროექტში YouTube ბმული დატოვო ან მომავალში ვიდეოებს ცალკე ჰოსტინგი მიუჩინო. შენი პლეერი ორივე მიდგომას მხარს უჭერს. პირობები ატვირთვის დღესაც გადაამოწმე ქვემოთ მოცემულ ოფიციალურ გვერდებზე.

## 9. შემდეგი განახლებები

ყოველი ცვლილებისას:

1. შეცვალე საწყისი ფაილები `frontend`-ში.
2. შეამოწმე ადგილობრივად `npm run dev --prefix frontend`-ით.
3. გაუშვი `npm run build --prefix frontend`.
4. წინასწარი განხილვისთვის გაუშვი `netlify deploy --dir=dist --no-build`.
5. არჩეული ვერსიის მთავარ მისამართზე გადასატანად — `netlify deploy --dir=dist --no-build --prod`.

თუ Drag & Drop გამოიყენე, არსებული პროექტის **Deploys** გვერდზე ჩააგდე განახლებული `dist`; საწყისი Drop გვერდიდან ყოველ ჯერზე ახალი პროექტი არ შექმნა. თუ საიტი უკვე Public-ია, მისი production განახლებებიც საჯარო იქნება.
